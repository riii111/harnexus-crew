# OS境界

Unixソケットでの1行の往復と、子プロセスの実行。
結果型と失敗型は `share/boundary` にあり、このディレクトリのパッケージはそれを返す。

| パッケージ | 公開する関数                                                              |
| ---------- | ------------------------------------------------------------------------- |
| `socket`   | `exchange_line(path, line, timeout_ms)`                                   |
| `process`  | `run_process(file, args, input, cwd~, env~, timeout_ms~, kill_grace_ms~)` |
| `process`  | `run_command(file, args, env, timeout_ms?)`                               |
| `process`  | `run_inherited(file, args, env)`                                          |
| `unix`     | `errno_name`、`close_fd`                                                  |

`env` は子の環境の全体であり、親の環境を暗黙には引き継がない。
プロセスの生存確認は `store` の `process_alive` にあり、ここでは公開しない。

## 契約

ソケット:

- 接続・書き込み・EOFまでの受信を一つの締切で囲む。締切は `ETIMEDOUT`。
- 接続前の失敗は `connected` が偽で、行は送られていない。接続後の失敗と締切は真で、結果は不明。
- 接続は非ブロッキングで、`EAGAIN` などの未完了は10msずつ待って再試行する。Linuxで待ち行列が満杯のときは、締切まで再試行して `ETIMEDOUT`（未送信）になる。macOSは満杯だと即座に `ECONNREFUSED`。
- 空の行は接続の確認だけで、何も送らない。答えは末尾の空白をJavaScriptの `trimEnd` と同じ範囲で除く。

`run_process`:

- 子は新しいセッションとプロセス群の長になる。締切または出力が16MiBを超えると、群へSIGTERMを送り、`kill_grace_ms` 後にSIGKILL、さらに `kill_grace_ms` 後も生きていれば `started` が真の失敗にする。
- `ended` が `Exit` 以外のとき、子の結果は不明。出力は標準出力と標準エラーの合計で16MiBまで残し、超えた分は捨てる（子が詰まらないよう読み続ける）。
- 終了後は、群に残ったものをSIGKILLで片づけてから返す。取り消しや失敗で戻るときも、先に終了した長が回収済みであっても群を片づける。シグナルで終わった子の `status` は1。
- 名前だけのコマンドは、子の環境の `PATH` から探す。相対の要素（空の要素を含む）は、指定した `cwd` の下で探す。
- 起動の失敗（実行できない、`cwd` がない）は `started` が偽で、`cannot run X (ENOENT)` のようにerrno名を括弧で添える。これだけが「子は走っていない」と確定する。起動後の失敗はすべて真。
- 出力はバイト列のまま集めて最後にUTF-8へ復号する。不正な列はU+FFFDで、Node（`StringDecoder`）と同じ結果になる。

`run_command`（`execFile` の挙動）:

- どの終了コードも結果として返す。起動の失敗、締切、片方のストリームが16MiB超え、シグナル死は `CommandFailed`。上限は `execFile` と同じく、標準出力と標準エラーそれぞれに適用する。
- 失敗の `code` は、Nodeが失敗に付けるコードに対応する（起動できないときのerrno名、出力超えの `ERR_CHILD_PROCESS_STDIO_MAXBUFFER`）。締切とシグナル死には付かない。コードを括弧で添えて表示する呼び出し側（git）だけが `メッセージ (コード)` にする。
- 標準入力は起動直後に閉じ、読む子は入力の終わりを受け取る。締切ではSIGTERMを1回送るだけ。SIGTERMを無視する子は終わるまで待つ。群は作らない。

`run_inherited`:

- 親の標準入出力をそのまま渡し、終了コードを返す。シグナルで終わった子は128＋シグナル番号。待ちを取り消しても子は止めない。

fdと子の所有権:

- fdは作った関数が呼び出し側へ渡すか、同じ関数の中で閉じる。成功・失敗・取り消しのいずれでも、`run_process` と `run_command` は子を回収し、パイプを閉じてから戻る。
- 子に渡すのは標準入出力だけ。親が持つパイプの端と接続は `CLOEXEC` で作り、起動中の別の子に漏れない。

## 起動の方式

C内で `fork` から `exec` までを行い、結果を書き込み側が閉じるパイプで同期して読む。
自身をもう一度起動して `setpgid` と `exec` を行う方式は、起動した自身のコピーに内部の引数を受け付けさせ、同時に起動した別の子へ通知用の書き込み側が渡る恐れがあるため使わない。

- 通知用のパイプとパイプの端は、起動ごとに一つのロックの下で作って閉じる。
- 起動は `exec` の完了まで待つので、`exec` の直前で止まった子という途中の状態はない。
- 診断用の環境変数や注入点は製品に持ち込まない。注入が必要な試験は、接続の1回の試行を差し替える試験用の入口（`exchange_with`）で行う。

## 試験

記号で始まる名前の試験は `socket_wbtest.mbt` と `process_wbtest.mbt` にある。
種別の「実OS」は実際のソケット・プロセスで確かめ、「注入」は接続の試行を差し替えて確かめる。

| 試験       | 内容                                                                              | 種別 |
| ---------- | --------------------------------------------------------------------------------- | ---- |
| S1〜S5     | 往復、ソケットなし、無応答の締切、サーバーのないソケット、空の行による接続の確認  | 実OS |
| C1         | 満杯の待ち行列。macOSは即座の拒否、Linuxは締切                                    | 実OS |
| C2〜C4     | 未完了の接続の再試行と、接続・書き込み・読み取りが共有する締切                    | 注入 |
| C5、C6     | 締切を過ぎる遅い答え、読まない相手への書き込みが詰まる4MiBの行                    | 実OS |
| E1〜E4     | 起動の失敗（コマンドなし、実行権なし、インタプリタなし）と、127で終わるプログラム | 実OS |
| P1、P3〜P5 | 標準入力の受け渡し、SIGTERMを無視する孫と長の強制終了、16MiBを超える出力          | 実OS |
| B1〜B3     | 長が先に終了した群の取り消し、`run_command` のストリームごとの上限、相対の `PATH` | 実OS |

ほかに次を確かめる。

- 複数の子を同時に起動しても、結果が起動した子ごとに返る。
- 別の子の標準入力の書き込み側を持った状態で起動した子が、それを引き継がず、前者が遅れずに終わる。同時に起動した子が見るfdの一覧は、単独で起動したときと同じ。
- 失敗・取り消し・正常終了の後にfdが残らず、取り消しでは子とその群が消える。
- 標準入出力が閉じた状態でも、存在しないコマンドの起動は未起動の失敗になり、fdが残らない。
- UTF-8の分割、不正なバイト列、`trimEnd` の範囲、環境・作業ディレクトリ・PATHの探索。
- 群を抜けた孫が出力を持ち続け、締切でも止められない子は、`started` が真の失敗になる。
- `run_command` と `run_inherited` の各失敗。

## 試験の前提

- `moon test` は最大10件の試験を同時に動かす。fdの数や締切を測る試験は、試験用のロックで1件ずつ実行する。
- ソケットの試験は `/tmp` にUnixソケットを作る。ソケットの作成を禁じる環境では動かない。
- 子プロセスの試験は、`/bin` と `/usr/bin` の標準コマンドと `test/native/mocks` を使い、リポジトリ直下を現在のディレクトリとして動かす。
- `setsid` や `fork` の失敗は起こせないので試験していない。
